## 3. レビュー後の判定

文書上では、環境・雛形の準備から、機能単位のテスト先行開発、CI、配布物の評価、修正、正式版の公開までを追える構成になりました。必須の承認工程を残しつつ、ファイル数・再承認・検査の頻度を必要な範囲に抑える条件を記載しています。

これは、掲載予定の具体コマンドやツール設定が実機で成功したという判定ではありません。手順書本体、具体プロンプト、hooks・CI の設定、Excel のひな型は今後作成します。題材アプリの UI・保存方式などの選択も、既存の関連テーマにまとめて確定する必要があります。

実践検証では特に、Windows 11 amd64 の Go＋Wails v2 経路で、雛形起動、テストの失敗から成功への変化、hooks の停止・復帰、CI ランナーのテスト可能範囲、RC・正式版成果物の導入と評価を確認します。正式版 NG からの再評価も、実際の不具合または再現用シナリオで確認します。詳細は[作成方針の品質確認](creation-policy.md#14-作成と品質確認の進め方)に従います。

## 7. Go 製の開発支援ツールと task の追加

利用者の追加指示により、Excel ファイル作成・フィジビリティチェック・性能計測など自作する開発支援ツールを Go で開発し、タスクランナーに task（go-task）を採用する方針を反映しました。開発ホストは両方の導入済みを前提にします。make を共通手順の前提にしない理由は、Windows 11 の日本語環境での動作に対する利用者の懸念として記録しました。

| 整合を確認した点 | 反映した内容 |
| --- | --- |
| 言語の適用範囲 | 自作支援ツールは Go、製品本体・テストは採用構成を使用する。既存 SDK・計測手段を呼び出し、必要な処理を自作する範囲を明示した |
| 準備の順序 | 工程2で Go・task を確認し、工程19〜21の hooks 準備で最小の Go ツール・Taskfile、工程22で製品構成のタスクを用意する。製品 SDK 導入まで hooks が作れない依存関係を避けた |
| ホストと CI | ホストは導入済みの確認から始め、CI では採用版と SDK・依存を用意する。同じ Taskfile を使い、ユーザー担当の公開・送信操作とビルド・検査を分けた |
| Excel 生成と結果保存 | Go の生成処理、14列・ID・日本語表示の確認、生成元と版、記入済み結果を上書きしない条件を対応付けた |
| 実行と再開 | Windows の日本語環境・パス・終了コード、Go ツールと task の版、再ビルド、計測条件・判定基準、実行タスクと入力・結果の記録を追加した |
| 文書とコードの配置 | 手順書側には説明・ひな型・例を、アプリ側には Go ソース・依存・Taskfile を置く。`manual/tools/` は AI エージェントの説明用であることを明記した |

方針の正本は[開発支援ツールと task](creation-policy.md#123-開発支援ツールと-task)です。Task のシェルと OS 対応、導入、Go の依存管理は同節の公式資料で確認しました。手順指針・配置計画・題材・引き継ぎ・作業単位・手順書入口も更新しました。採用版・ライブラリ・タスク名・Go モジュールの配置は執筆時に具体化し、Go ツール・Taskfile・Excel ファイルの実装と実行検証は引き続き未実施です。
